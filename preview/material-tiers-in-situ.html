Three findings from this read, not yet in the spec.
1 — Chrome ships two different light values. --material-chrome-bg is 75% and feeds the navbar-materialize keyframe; @utility material-chrome is bg-white/55. A navbar that animates in lands at 75% and any static chrome sits at 55%. RECONCILIATION recorded 55, DESIGN.md recorded 75 — both are in the code, which is the actual defect.
2 — globals.css's own doc comment is the source of the spec's wrong numbers. The comment block above the utilities still reads thin ~45%, regular ~85%, thick ~100%, chrome 75% and "DARK MODE (black overlays)". The utilities directly beneath it say 30/55/75 and white. So §3 is not spec drift — the spec faithfully transcribed a stale comment. Fix the comment in the same PR or the next reader regenerates the same error.
3 — The tiers are not evenly spaced and the usage table is stale. Light steps 10 → 30 → 55 → 75; the comment claims thick is "~100% effective" but it is 75%, i.e. still translucent. Anything relying on thick to fully occlude is relying on a value that does not exist — which is exactly why .popover-surface had to be added as a solid fill.
